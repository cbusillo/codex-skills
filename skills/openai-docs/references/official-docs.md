# Official documentation, API references, and ChatGPT Work

Use this route for specialized product/API documentation work when fetched
pages leave source selection, API schemas or implementation unresolved. Follow
`SKILL.md`'s official-source order and credential boundary: an embedded OpenAI
question still requires official search and actual page retrieval before local
inspection, planning or implementation. Narrow Codex questions and mixed
Chat/Work/Codex comparisons remain documentation-first.

## Resolve the remaining gap

1. Narrow a noisy query; open a plausible official page rather than relying on
   snippets. Use an already-available documentation index only when there is no
   clear search query.
2. For API schemas, required fields, parameters or endpoint shapes, use an
   already-available OpenAPI/specification capability when it directly resolves
   the question. Otherwise verify against the fetched official API guide or
   reference.
3. Cite the exact official page supporting each consequential claim. Keep
   examples minimal and paraphrase rather than quote at length. State when
   sources do not establish a capability, parameter, price or availability.

Preserve an explicitly requested model in both search and answer. Current or
latest model recommendations belong to the model-selection route; a specific
Codex feature, error, setting or requested citation is not manual-first.

## ChatGPT Work and mixed surfaces

Treat Chat/Work/Codex comparisons as ChatGPT Work documentation. Search
`learn.chatgpt.com` and open or fetch the relevant page. Useful starting pages:

- `https://learn.chatgpt.com/docs/use-chatgpt`
- `https://learn.chatgpt.com/docs/get-started-with-work`

An API question asked from Work still uses the relevant API guide; the host
surface does not make it a Work product question.

Separate documented user-facing purposes from claims about underlying models,
hard capability boundaries, file/context inheritance, exact UI labels, account
entitlements and rollout availability. When these cannot be verified, cite the
closest allowed official source and state the uncertainty.
